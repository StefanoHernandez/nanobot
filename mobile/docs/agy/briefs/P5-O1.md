## Context
When the phone is disconnected (`sessionStore` state is `"offline"` or `"reconnecting"` or `"connecting"`), typing a message and pressing Send in the Composer should not fail or drop the message into a dead WebSocket. Instead:
1. Messages typed while disconnected are queued in **MMKV per profile and per chat**, shown above the composer as **"In attesa" / "Pending"**, and each queued item has a **Cancel** action.
2. When the connection returns (`state === "open"`), once the thread's `loaded` state is true and the chat is idle (`!running && !uploading`), queued messages for that chat are sent **in FIFO order**, one turn at a time.
3. **Profile-switch safety (hard requirement):** queued messages from profile A must never be sent to profile B, and after a profile switch (`sessionStore` profile changes or resets), any pre-existing queued items for the newly opened profile must **not** auto-send immediately — they stay paused ("In attesa — tocca per inviare" / "Pending — tap to send") until the user taps Send/Retry on them or until a *subsequent* offline→online reconnect happens within the same active profile session.

### 1. `mobile/src/extras/outbox.ts`
Build the MMKV-backed outbox store and flush controller:
- Types:
  ```ts
  export type OutboxItem = {
    id: string;
    text: string;
    opts?: SendOpts;
    createdAt: number;
    /** True when loaded from disk after a cold start or profile switch; prevents auto-send until user taps Send or a same-session reconnect occurs. */
    paused?: boolean;
  };
  ```
- Storage key in `kv`: `outbox:v1:${profileId}` storing a JSON map `Record<string, OutboxItem[]>` (keyed by `chatKey`).
  - Whenever items are loaded from `kv` on profile bind/switch, mark loaded items with `paused: true` so switching profiles NEVER triggers an automatic flush of old queued messages.
  - Items enqueued during the *current* live profile session while disconnected have `paused: false`, so when the connection transitions back to `"open"` within the same profile session, they auto-flush in order.
- Zustand store `outboxStore`:
  - `activeProfileId: string | null`
  - `queues: Record<string, OutboxItem[]>` (for the active profile)
  - `syncProfile(profileId: string | null): void` — if `profileId !== activeProfileId`, loads that profile's queues from `kv` with `paused: true` on all items (or `{}` if `profileId` is null).
  - `enqueue(chatKey: string, text: string, opts?: SendOpts): OutboxItem | null` — appends a new item (`paused: false`), persists to `kv`, returns the item.
  - `cancel(chatKey: string, itemId: string): void` — removes the item from `chatKey`'s queue and persists to `kv`.
  - `resumeItem(chatKey: string, itemId: string): void` — sets `paused: false` on that item (or all items in `chatKey`) and triggers a flush attempt if `sessionStore.getState().state === "open"`.
  - `flushNext(chatKey: string): boolean` — checks all guards:
    1. `sessionStore.getState().state === "open"` and `sessionStore.getState().session` is non-null;
    2. `sessionStore.getState().profile?.id === activeProfileId` (profile-switch guard);
    3. `const slice = threadStore.getState().threads[chatKey];` — `slice?.loaded === true && !slice.running && !slice.uploading`;
    4. The first item `head` in `queues[chatKey]` exists and `!head.paused`.
    If all 4 hold, pops `head`, persists to `kv`, and calls `threadStore.getState().send(session, chatKey, head.text, head.opts)`. (When that turn finishes and `running` goes back to `false`, the next item in the queue will flush automatically!)

### 2. `mobile/src/extras/OutboxBar.tsx`
Component `OutboxBar({ chatKey }: { chatKey: string })`:
- Subscribes to `sessionStore` (`profile`, `state`), `threadStore` (`loaded`, `running`, `uploading`), and `outboxStore` (`queues[chatKey]`).
- Calls `outboxStore.getState().syncProfile(profile?.id ?? null)` when `profile?.id` changes.
- Runs an effect that calls `outboxStore.getState().flushNext(chatKey)` whenever `state === "open"`, `loaded === true`, `!running`, `!uploading`, and there is an unpaused item at the head of `queues[chatKey]`.
- Renders `null` when `queues[chatKey]` is empty.
- Otherwise renders a compact list above the Composer:
  - Each `OutboxItem` row shows:
    - A status badge/label: `t("outbox.pending")` ("In attesa" / "Pending"), or `t("outbox.paused")` when `item.paused` is true;
    - The message text (1 line, ellipsized) and attachment count if `item.opts?.files?.length`;
    - When `item.paused && state === "open"`, an `IconButton` (`icon="send"`, `accessibilityLabel={t("outbox.sendNow")}`) that calls `outboxStore.getState().resumeItem(chatKey, item.id)`;
    - A Cancel `IconButton` (`icon="close"`, `accessibilityLabel={t("outbox.cancel")}`, ≥ 48 dp touch target) that calls `outboxStore.getState().cancel(chatKey, item.id)`.

## Tests (write first, see them fail, then implement)
In `mobile/test/extras/outbox.test.tsx` (exercise the real `outboxStore`, `OutboxBar`, and `Composer` with `kv` and `threadStore` — do **not** mock `outboxStore`):
1. **Queue while offline:** when `sessionStore` state is `"offline"`, pressing Send in `Composer` enqueues the message in `outboxStore` (and `kv`), clears the composer draft, does not call `session.client.sendMessage`, and `OutboxBar` renders the message with the "Pending" label.
2. **Cancel:** pressing the Cancel button on a queued row removes it from `outboxStore` and `kv`, and when the session later becomes `"open"` nothing is sent.
3. **FIFO send on reconnect (waiting for hydrate & idle):** enqueue `"first"` and `"second"` while `"reconnecting"`. Transition `sessionStore` to `"open"` while `threadStore` has `loaded: true, running: false`:
   - `"first"` is sent immediately (`sendMessage` called once with `"first"`), setting `running: true`;
   - `"second"` waits while `running: true`;
   - once the first turn ends (`running: false`), `"second"` is sent automatically.
4. **Profile switch never auto-sends:** enqueue a message under profile `p1`. Switch `sessionStore` to profile `p2` (`state: "open"`): nothing from `p1` is visible or sent. Switch back to `p1` (`state: "open"`): the item loaded from `kv` has `paused: true` and does **not** auto-send on profile switch until the user taps `sendNow`.
