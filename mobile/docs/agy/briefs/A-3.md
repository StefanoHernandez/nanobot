## What to build
1. **Zoom and pan for SVG and Mermaid**, inside the shell HTML:
   - pinch (two pointers) to zoom between 0.5x and 6x, drag to pan, double-tap to toggle "fit" / 2x;
   - use CSS `transform` on a wrapper with `touch-action: none`. Keep it smooth (requestAnimationFrame) and honour `prefers-reduced-motion` (no animated transition).
2. **HTML artifacts:** a toolbar toggle "Adatta / 100%": fit-to-width scaling vs. the artifact's own viewport.
3. **Landscape:** a rotate button in the viewer header unlocks orientation (`expo-screen-orientation`) for the viewer only. Lock back to portrait when the viewer unmounts.
4. **App theme in the artifact:**
   - pass `scheme: "light" | "dark"` and our theme colours into `buildShellHtml`;
   - Mermaid initialises with `theme: "dark"` or `"default"` plus `themeVariables` from our tokens (background `popover`, text `popoverForeground`, lines `border`, primary `chartInput`);
   - the page background follows `popover`.
5. **Export:**
   - **PNG** (SVG and Mermaid): the shell renders the SVG to a canvas at 2x, then posts `{type:"png", dataUrl}`. The viewer writes it to `Paths.cache/artifacts/<name>.png`, then opens the share sheet. Cap the size at 4096px on the long side.
   - **PDF** (HTML, SVG, Mermaid, Markdown): `expo-print` `printToFileAsync({ html })` with the same shell HTML, then the share sheet.
   - Both actions go in a viewer "Esporta" menu (sheet), with i18n labels.
6. **postMessage:** keep the protocol backward compatible. Validate every incoming message type and size (data URL ≤ 20 MB, else ignore plus toast).
