This is Phase 2. Read `mobile/docs/agy/README.md` first; the rules are unchanged.

- **Branch:** `agy/P2-A1`, which Claude creates from `dev`.
- **Before starting:** `cd mobile && npm ci`.

## Context
The agent can send files in the chat. Today `FileCard` (`mobile/src/screens/thread/media/MediaViews.tsx`) downloads a file and opens it in an external Android app. For readable formats we want an **in-app full-screen viewer**, similar to Claude's artifacts: open the file, read it nicely formatted, then save or share it.

Existing code (read it; edit only what is listed under "Files"):
- `mobile/src/screens/thread/media/media.ts`:
  - `downloadMedia(url, name): Promise<localUri>` (cached, atomic)
  - `openLocal(localUri, ext)`, which opens the file in an external app
  - `shareMedia(localUri)`
  - `extOf(m)`
  - `mediaName(m)`
- `mobile/src/ui/markdown/Markdown.tsx`: `Markdown({ text, fontSize? })`
- `mobile/src/ui/markdown/CodeBlock.tsx`: `CodeBlock({ code, lang? })`, with syntax colors
- `expo-file-system` (SDK 57, new API): `new File(uri).text()` reads text, and `File.size` gives the size. Check the SDK 57 docs: https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/
- UI kit `mobile/src/ui/components`, `useTheme()`, `useT()`.

## What to build
**Files:**
- `mobile/app/viewer.tsx`: a route with query params `uri` (the local `file://` uri, **never the remote URL**) and `name`.
- `mobile/src/screens/viewer/FileViewer.tsx`: the logic and UI.
- `mobile/src/screens/viewer/formats.ts`: pure helpers.
- `mobile/src/screens/thread/media/MediaViews.tsx`: **only** the `FileCard` open handler, so that viewable files navigate to the viewer instead of the external app.
- i18n keys `viewer.*` in it and en.
- Test: `mobile/test/screens/viewer.test.tsx`.

**`formats.ts` (pure, tested):**
- `viewerKind(name): "markdown" | "code" | "json" | "csv" | "text" | null`
  - markdown: `.md`, `.markdown`
  - json: `.json`
  - csv: `.csv`, `.tsv`
  - text: `.txt`, `.log`
  - code: `.py .js .ts .tsx .jsx .sh .yaml .yml .toml .html .css .sql .go .rs .java .kt .c .cpp .h .rb .php .xml .ini .env`
  - `null` for anything else, such as pdf, pptx or images. Those keep the external-app path.
- `langOf(name)`: the extension without the dot, for `CodeBlock`.
- `parseCsv(text, sep)`: handles quoted fields with commas and `""` escapes. Separator is `,`, or `\t` for `.tsv`.
- `prettyJson(text)`: `JSON.stringify(JSON.parse(text), null, 2)`. On a parse error, return the original text unchanged.

**FileViewer screen:**
- **Header:** back `IconButton`, the file name (one line, ellipsized), and on the right:
  - **Copy** (`expo-clipboard`, already an Expo module; install it with `npx expo install expo-clipboard` if missing and say so in the report). It copies the whole text and shows a toast.
  - **Share**, which calls `shareMedia(uri)`.
  - **Open with…**, which calls `openLocal(uri, ext)`.
- **Body,** scrollable:
  - markdown renders with `<Markdown text/>`;
  - code renders with `<CodeBlock code lang/>`, with horizontal scroll for long lines;
  - json is pretty-printed, then shown with `CodeBlock lang="json"`;
  - csv renders as a table: the first row is the header (bold), with horizontal scroll and a sticky header if easy. Cap it at 500 rows and show "Mostrate 500 di N righe" / "Showing 500 of N rows".
  - text renders as monospace and selectable.
- **Large files:** if the file is larger than 2 MB, do not read it. Show "File troppo grande per l'anteprima" / "File too large to preview" plus the Open with… button.
- **Read errors** show an inline error plus Open with….
- Colors come from the theme, strings from i18n, touch targets are at least 48 dp, and safe-area insets are respected.

**FileCard change:** in its Open handler, after `downloadMedia`:
- if `viewerKind(name)` is not null, call `router.push({ pathname: "/viewer", params: { uri: localUri, name } })`;
- otherwise call `openLocal` as today.

Long-press still shares.

## Tests (write first, see them fail, then implement)
- `viewerKind`: `notes.md` gives markdown, `a.py` gives code, `data.json` gives json, `t.tsv` gives csv, `deck.pptx` gives null.
- `parseCsv`: `a,b\n"x,1","he said ""hi"""` gives `[["a","b"],["x,1",'he said "hi"']]`.
- `prettyJson`: invalid JSON is returned unchanged.
- FileViewer with a mocked `File`:
  - a `.md` file renders its heading text;
  - a `.csv` file with 3 rows shows the header cells;
  - a file over 2 MB shows the too-large message and does not call `.text()`.
- FileCard: Open on `notes.md` pushes `/viewer` with the **local** uri. Open on `deck.pptx` calls `openLocal`. The remote URL never appears in the router params.
