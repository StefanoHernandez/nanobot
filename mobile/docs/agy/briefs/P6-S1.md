## Context
We want a lightweight, high-signal **Hybrid Memory** system (`nanobot/ext/memory_hybrid.py`) running in-process inside the fork's gateway on luffy (Arduino UNO Q, 3.6 GB RAM):
1. **No conflict with upstream `Dream` (`MEMORY.md`):** Upstream `Dream` (`nanobot/agent/memory.py`) owns `MEMORY.md` via `GitStore`. Our hybrid memory stores structured facts, lessons, embeddings, and entity relations in a dedicated SQLite database (`~/.nanobot/ext_memory.db`, WAL mode).
2. **Three storage layers in one SQLite DB:**
   - **Facts & Lessons (`facts` table + FTS5 index `facts_fts`):** Each fact has `id`, `content`, `category` (`"fact" | "preference" | "lesson" | "project"`), `tags_json`, `status` (`"active" | "pending"`), `source_session`, `created_at_ms`, `updated_at_ms`, and optional `embedding` (`BLOB`, float32 array).
   - **Approval queue (`status = "pending"`):** Lessons or facts extracted automatically or marked `require_approval=True` wait in `"pending"` status until the user approves them in the mobile app's **Memoria** screen (`status -> "active"`). Only `"active"` facts are returned to the agent in `memory_recall`.
   - **Relation Graph (`entities` and `relations` tables):** Entities (`name`, `kind`, `summary`) and directed relations (`source_entity`, `relation`, `target_entity`, `fact_id`) passed by the agent or user, with multi-hop traversal (`memory_related`).
3. **Hybrid scoring (Lexical FTS5 + Optional Lazy ONNX Vectors):**
   - Always indexes facts in SQLite `FTS5` (or `LIKE` fallback if FTS5 is unavailable) for fast, zero-RAM BM25 search.
   - If an embedding provider/ONNX session is registered (or optional local ONNX `multilingual-e5-small` is available), blends cosine similarity with lexical score, and unloads any ONNX session after 300 s of inactivity so luffy's RAM stays free.
4. **Two faces from one module:**
   - **Agent face:** 3 tools in `nanobot/agent/tools/memory_hybrid.py` (`memory_remember`, `memory_recall`, `memory_related`), auto-discovered by `ToolLoader.discover()` (`nanobot/agent/tools/loader.py`) with `_scopes = {"core", "subagent"}`.
   - **HTTP/WS face for mobile & WebUI:** `/api/ext/memory/*` routes + WebUI mutations `memory.create`, `memory.approve`, `memory.delete`.

### 1. `nanobot/ext/memory_hybrid.py`
Implement `HybridMemoryStore`:
- Constructor `HybridMemoryStore(db_path: Path | None = None, embedder: Callable[[str], list[float]] | None = None)`:
  - Defaults `db_path` to `get_data_path() / "ext_memory.db"`.
  - Creates tables `facts`, `entities`, `relations`, and FTS5 virtual table `facts_fts` (kept in sync on insert/update/delete).
- Core methods:
  - `remember(content: str, *, category: str = "fact", tags: list[str] | None = None, entities: list[dict[str, str]] | None = None, relations: list[dict[str, str]] | None = None, status: Literal["active", "pending"] = "active", source_session: str | None = None) -> dict[str, Any]`:
    - Inserts fact into `facts` (and `facts_fts`).
    - Upserts any `entities` (`[{"name": "luffy", "kind": "device", "summary": "Arduino UNO Q server"}]`, normalized case-insensitively by `name`).
    - Inserts any `relations` (`[{"source": "stefano", "relation": "runs_on", "target": "luffy"}]`) linked to `fact_id`.
    - Returns the serialized fact dict.
  - `recall(query: str, *, limit: int = 10, category: str | None = None) -> list[dict[str, Any]]`:
    - Searches **only `status = 'active'`** facts.
    - Combines FTS5 / token match score + optional vector cosine similarity (when `embedder` is present), plus a boost if `query` matches an entity linked to the fact.
    - Returns top `limit` facts ordered by score descending, each including its linked `relations`.
  - `related(entity: str, *, depth: int = 2) -> dict[str, Any]`:
    - Performs a BFS up to `depth` hops starting from `entity` (case-insensitive match).
    - Returns `{"root": entity, "entities": [...], "relations": [...], "facts": [...]}`.
  - `list_facts(*, status: str | None = None, category: str | None = None, query: str | None = None, limit: int = 100) -> list[dict[str, Any]]`
  - `approve_fact(fact_id: str) -> dict[str, Any] | None`: sets `status = "active"`, updates `updated_at_ms`, returns updated fact.
  - `delete_fact(fact_id: str) -> bool`: removes fact and its `facts_fts` row and orphaned `relations`.
  - `graph_snapshot(entity: str | None = None, limit: int = 100) -> dict[str, Any]`: returns `{"entities": [...], "relations": [...]}` for the app's Graph tab.
- HTTP dispatcher `dispatch_memory_routes(request: WsRequest, got: str, *, store: HybridMemoryStore, check_api_token: Callable[[WsRequest], bool], parse_query: Callable[[str], dict[str, list[str]]], parse_body: Callable[[WsRequest], dict[str, Any]]) -> Response | None`:
  - All `/api/ext/memory*` routes require `check_api_token(request)` (return 401 otherwise).
  - `GET /api/ext/memory`: query params `q`, `status`, `category` → returns `{"facts": store.list_facts(...), "pending_count": len(store.list_facts(status="pending"))}`.
  - `GET /api/ext/memory/graph`: query param `entity` → returns `store.graph_snapshot(entity)` (or `store.related(entity)` if `entity` is non-empty).
  - `POST /api/ext/memory/create` (and WebUI mutation `"memory.create"`): body `{ content, category?, tags?, entities?, relations?, status? }` → calls `store.remember(...)`, returns `{"fact": fact, "facts": store.list_facts()}`.
  - `POST /api/ext/memory/approve` (and WebUI mutation `"memory.approve"`): body `{ id }` → calls `store.approve_fact(id)`, returns `{"ok": True, "facts": store.list_facts()}`.
  - `POST /api/ext/memory/delete` (and WebUI mutation `"memory.delete"`): body `{ id }` → calls `store.delete_fact(id)`, returns `{"ok": True, "facts": store.list_facts()}`.

### 2. `nanobot/agent/tools/memory_hybrid.py`
Implement 3 `Tool` subclasses (`_scopes = {"core", "subagent"}`):
- `MemoryRememberTool` (`name = "memory_remember"`): parameters `content` (required), `category` (`"fact"|"preference"|"lesson"|"project"`), `tags` (list of strings), `entities` (list of `{name, kind, summary}`), `relations` (list of `{source, relation, target}`), `require_approval` (bool, default `False`; when `True` or `category == "lesson"`, saves with `status="pending"`).
- `MemoryRecallTool` (`name = "memory_recall"`): parameters `query` (required), `category` (optional), `limit` (int, default 10).
- `MemoryRelatedTool` (`name = "memory_related"`): parameters `entity` (required), `depth` (int, 1–3, default 2).

## Tests (write first in `tests/test_memory_hybrid.py`)
1. `remember` + `recall`: active facts are returned ranked by relevance; `pending` facts (`status="pending"`) are **excluded** from `recall` until `approve_fact(id)` is called, after which `recall` returns them.
2. Hybrid vector + lexical ranking: with a fake `embedder` passed to `HybridMemoryStore`, a semantically matching fact with different wording is recalled via cosine similarity.
3. Multi-hop relation graph (`related`): `A -> runs_on -> B` and `B -> located_in -> C`; `related("A", depth=2)` returns both hops (`A`, `B`, `C`) and their linked facts.
4. `delete_fact`: deletes the fact from `facts`, `facts_fts`, and cleans up its relations.
5. Agent tools (`MemoryRememberTool`, `MemoryRecallTool`, `MemoryRelatedTool`): discovered by `ToolLoader().discover()` and execute end-to-end against a temp `HybridMemoryStore`.
6. HTTP API (`/api/ext/memory`, `/api/ext/memory/create`, `/api/ext/memory/approve`, `/api/ext/memory/delete`, `/api/ext/memory/graph`): rejects unauthenticated calls with 401 and performs full CRUD + approval when authenticated.
