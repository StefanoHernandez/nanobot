# P5-V1: Interactive artifacts and in-app document previews (owner: agy)

The user wants to open what the agent produces **inside the app, like Claude artifacts**:
- interactive HTML/SVG pages and Mermaid diagrams;
- previews of PDF, Word (docx), PowerPoint (pptx) and Excel (xlsx).

Read `mobile/docs/agy/README.md` first.

- **Branch:** `agy/P5-V1`, which Claude creates from `dev`.
- **Before starting:** `cd mobile && npm ci`.

## Context: read these files first, then extend them
- `mobile/src/screens/viewer/formats.ts`: `viewerKind(name)`. It returns `null` today for pdf, docx, pptx and html, which then open externally.
- `mobile/src/screens/viewer/FileViewer.tsx` and `mobile/app/viewer.tsx`: the existing viewer for markdown, code, json, csv and text, and how it gets the downloaded local file.
- `mobile/src/screens/thread/media/{media.ts,MediaViews.tsx}`: FileCard, download to cache, and "open with external app".

- The markdown renderer for chat code blocks (find where fenced code is rendered under `mobile/src/ui/markdown/`).

## What to build
**1. `mobile/src/screens/viewer/ArtifactWebView.tsx`**
- One sandboxed WebView component.
- It takes `{ kind, html?, base64?, onFallback }` and builds a self-contained shell HTML string, loaded with `source={{ html, baseUrl: "about:blank" }}`.
- Renderer libraries load from **pinned exact versions** on `https://cdn.jsdelivr.net/npm/<pkg>@<x.y.z>/...`. Put all URLs and versions in one constant.

| kind | Renderer in the WebView |
|---|---|
| `html` | The file's own HTML, with JS enabled (interactive). |
| `svg` | The SVG inline in a centered, zoomable page. |
| `mermaid` (`.mmd`, `.mermaid`) | `mermaid` renders the source. |
| `pdf` | `pdfjs-dist`: all pages as canvases, with lazy rendering on scroll and pinch-zoom. |
| `docx` | `docx-preview` (needs `jszip`). |
| `pptx` | `pptx-preview`: slides stacked vertically, scaled to the width. |
| `xlsx` / `xls` | SheetJS (`xlsx`): a sheet tab bar plus an HTML table. |

- Binary data never goes in a URL. **Big files must work**, so do not inject the whole file as one base64 string.
  - **Chunked transfer.** The page posts `{"type":"need","offset","length"}`. RN reads that slice with expo-file-system (`readAsStringAsync` with `encoding: base64`, `position`, `length`, in 1 MB chunks) and pushes it back with `webViewRef.injectJavaScript("window.__chunk(<offset>, '<b64>')")`. The page assembles the chunks into a `Uint8Array`/`Blob`.
    - Accept `need` messages only with integer `offset` and `length` inside the file size; ignore anything else.
  - **PDF streams on demand.** Use pdf.js `PDFDataRangeTransport` (range loading) fed by the same `need`/`__chunk` protocol. Only the visible pages are fetched and rendered, so any size works. Render pages lazily as they scroll into view and free canvases far off-screen.
  - **docx, pptx and xlsx** need the whole zip. Load it by chunks, with a progress bar ("Caricamento 12/48 MB").
    - xlsx renders the first 500 rows per sheet, with a "Mostra altre righe" / "Show more rows" button; never build one giant table.
    - pptx renders slides lazily, the visible ones first.
  - **html, svg and mermaid** are text: inject them directly when ≤ 2 MB, otherwise by chunks too.
- Theme: page background and foreground from the app theme (light/dark).
- The renderer posts `{"type":"ready"}` or `{"type":"error"}` via `window.ReactNativeWebView.postMessage`.
  - `onMessage` **only** accepts those two shapes and ignores everything else. On error, or after a 20 s timeout with no ready, call `onFallback`.

**2. Security: required, and tested where possible**
WebView props:
- `javaScriptEnabled`
- `domStorageEnabled={false}` and `incognito`
- `allowFileAccess={false}`, `allowFileAccessFromFileURLs={false}` and `allowUniversalAccessFromFileURLs={false}`
- `mixedContentMode="never"`
- `setSupportMultipleWindows={false}` and `javaScriptCanOpenWindowsAutomatically={false}`
- `geolocationEnabled={false}` and `mediaCapturePermissionGrantType="deny"`

Injected CSP: the **first element in `<head>`**, before any agent content, is a `<meta http-equiv="Content-Security-Policy">` with:

```
default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' https://cdn.jsdelivr.net https://cdnjs.cloudflare.com https://unpkg.com; style-src 'unsafe-inline' https://cdn.jsdelivr.net https://cdnjs.cloudflare.com https://fonts.googleapis.com; font-src data: https://fonts.gstatic.com https://cdn.jsdelivr.net; img-src data: blob: https:; media-src data: blob:; worker-src blob:; connect-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'
```

The pdf.js worker must work with `worker-src blob:`. If it does not, use the worker-less mode.

Navigation:
- `onShouldStartLoadWithRequest` allows only the initial `about:blank` / `data:` load.
- Any other navigation is blocked. If it is http(s), show a confirm `Dialog`, "Aprire nel browser?" / "Open in browser?", then `Linking.openURL`.

Never pass the session, API token, auth headers, or the signed media URL into the WebView. Never log file contents or URLs.

Size handling. There is never a plain "too big, no preview":

| Size | Behaviour |
|---|---|
| PDF, any size | Streamed by range. |
| docx, pptx or xlsx ≤ 150 MB | Full preview loaded by chunks. Above 50 MB, first show a notice "File grande (120 MB): l'anteprima può richiedere tempo" / "Large file (120 MB): preview may take a while" with "Apri anteprima" / "Open preview" and "Apri con…" / "Open with…". |
| pptx > 150 MB | **Light preview.** Read `docProps/thumbnail.jpeg` and the `ppt/media/*` images from the zip with JSZip over the chunk protocol (zip central directory only, no full load). Show the cover plus an image gallery. |
| docx > 150 MB | **Light preview.** Read `word/document.xml` from the zip and show the plain text of the first ~200 paragraphs. |
| xlsx > 150 MB | **Light preview.** Read `xl/sharedStrings.xml` plus the first sheet and show the first 200 rows. |
| html, svg or mermaid > 10 MB | Shown as code in the existing code viewer, with an "Anteprima comunque" / "Preview anyway" button. |

Fallbacks:
- If the renderer fails, the CDN is unreachable (offline), or it times out, `onFallback` shows "Anteprima non disponibile" / "Preview not available" with the existing "open with external app" button.
- If the device runs out of memory (WebView `onRenderProcessGone`), show the light preview and do not crash.

**3. Wire it in**
- `formats.ts`: add the kinds `html`/`htm`, `svg`, `mmd`/`mermaid`, `pdf`, `docx`, `pptx`, `xlsx`/`xls`. Keep `doc`, `ppt` and others as external.
- `FileViewer.tsx`: for these kinds, render `ArtifactWebView`. The header keeps Share and "Apri con…" / "Open with…" (external).
- Chat code blocks: fenced blocks with language `html`, `svg` or `mermaid` get a small "Anteprima" / "Preview" button. It opens the viewer with the block content (pass it through an in-memory store or a temp cache file, **not** route params).
- FileCard: tapping a supported doc opens the in-app viewer instead of the external app. A long-press or the menu still offers "Apri con…".
- i18n `artifact.*` in it and en.

## Tests (write first, see them fail, then implement)
`mobile/test/screens/artifacts.test.tsx`. Mock `react-native-webview` to capture its props.
- `viewerKind`: `report.pdf` → `pdf`, `a.docx` → `docx`, `s.pptx` → `pptx`, `x.xlsx` → `xlsx`, `p.html` → `html`, `d.mmd` → `mermaid`, `old.doc` → `null`.
- The shell HTML starts with the CSP meta before the agent content, and contains `connect-src 'none'`.
- The WebView props include `allowFileAccess: false`, `incognito: true` and `setSupportMultipleWindows: false`.
- `onShouldStartLoadWithRequest({url:"https://evil.example"})` returns false and opens the confirm dialog. Confirm calls `Linking.openURL` once.
- `onMessage` with `{"type":"error"}` calls `onFallback`. A random message such as `{"type":"navigate"}` is ignored.
- Chunk protocol:
  - `need` with offset 0 and length 1048576 reads that slice and calls `injectJavaScript` with `__chunk(0,`;
  - `need` with a negative offset, or one beyond the file size, is ignored.
- Size routing:
  - a 60 MB docx shows the "large file" notice first;
  - a 200 MB pptx goes to the light preview;
  - an 11 MB html opens as code with a "Preview anyway" button;
  - a 500 MB pdf still uses the streamed PDF viewer.
- `onRenderProcessGone` shows the light preview.
- A chat code block with `html` shows the Preview button, and with `python` it does not.
