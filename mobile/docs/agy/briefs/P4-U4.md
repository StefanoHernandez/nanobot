## Context
Logic is done; do not edit `src/ecosystem/*`.

`mobile/src/ecosystem/automations.ts`:
- `useAutomations()` returns `{ jobs, loading, error, refresh, run, enable, disable, delete, update, changeChat, result }`.
- `groupByDay(jobs, now)` returns groups `today | tomorrow | later`.
- `fetchAutomationChats(session, id)` and `fetchAutomationRunResult(session, id, runAtMs)`.
- The types `SessionAutomationJob` etc. are in `mobile/vendor/nanobot/webui/src/lib/types.ts`.
- Read `mobile/test/ecosystem/apps-skills-automations.test.ts` for how they behave.

Copy UI patterns from the P4-U2 Apps screen (dialogs, sheets, toasts). Message rendering: reuse the existing Markdown renderer.

## What to build
1. Enable "Automazioni" in `mobile/app/ecosystem/index.tsx`, routing to `/ecosystem/automations`.
2. `mobile/app/ecosystem/automations.tsx` plus `mobile/src/screens/ecosystem/automations/*`.
   - **Calendar list.** A SectionList from `groupByDay(jobs, Date.now())` with the headers Oggi, Domani, Più avanti (Today, Tomorrow, Later). Each row shows:
     - the name or the first line of the message;
     - the human schedule;
     - the next run time (locale-formatted);
     - the target chat title;
     - an enabled Switch that calls `enable`/`disable`, with a loading state and an error toast.

     Pull-to-refresh, plus an empty state.
   - **Job sheet** (tap on a row):
     - **"Esegui ora" / "Run now"** goes behind a confirm: "Esegue subito l'automazione sul computer host". Confirm calls `run(id)` **exactly once**, with the button disabled while it runs. It then shows the result view: `result(...)` / `fetchAutomationRunResult` rendered as Markdown, with a loading state.
     - **Edit** the message and schedule with `update` (snake_case is handled by the logic). Validate non-empty fields, and show server errors inline.
     - **Change chat** opens a picker loaded from `fetchAutomationChats`, then calls `changeChat`.
     - **Delete** uses a destructive confirm, then calls `delete(id)` and closes the sheet.
     - **Past runs.** If the job payload exposes past runs, list them, and tapping one opens its result.
3. i18n `automations.*` in it and en.

## Hard rules
- No `client.onChat`. Do not edit `mobile/vendor/**`, `src/ecosystem/*` or `src/settings/*`.
- Theme colors, 48 dp touch targets, safe area, KeyboardAvoidingView `behavior="padding"` in the edit sheet.

## Tests (write first, see them fail, then implement)
`mobile/test/screens/ecosystem-automations.test.tsx`, mocking `useAutomations` and the fetchers.
- Run now opens a confirm. Confirm calls `run("j1")` exactly once (a double tap still makes only 1 call), then the result text is shown.
- The enable switch off calls `disable("j1")`, and on calls `enable`.
- Delete opens a confirm, and confirm calls `delete("j1")` once.
- Calendar: a job due today and one due in 3 days render under "Oggi" and "Più avanti" respectively.
- Change chat: picking a chat calls `changeChat` with its key.
