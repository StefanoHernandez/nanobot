## What to build
**Files:** `mobile/src/ecosystem/apps.ts`, `mcp.ts`, `skills.ts` and `automations.ts`. Tests go in `mobile/test/ecosystem/apps-skills-automations.test.ts`.

The exported names are those in plan Task P4-C2:
- `useCliApps`
- `useFeatures`
- `useMcp`
- `useMcpOAuth`
- `useSkills`
- `useAutomations` with `groupByDay`
- `fetchAutomationChats`
- `fetchAutomationRunResult`

Every install, update or uninstall, and `feature.enable`:
1. checks `installGate(settings)` first. If it is not allowed, it throws or returns a `{ policy: true }` error **without calling the server**;
2. goes through `longMutation`;
3. re-fetches the list after `timedOut`.

## Hard exclusions (security; a test must prove them)
- `mcp.ts` has **no** custom or import server actions.
- `skills.ts` has **no** delete.
- Nothing calls `remote.*` or `api_service.*`. Nothing edits `tools.webui_allow_remote_package_install`.
- `useMcpOAuth`:
  - never logs the auth URL or the callback URL;
  - sends a pasted callback_url **once**;
  - stops polling at expiry and on unmount;
  - for device-code flows, sends cancel on unmount.
- Payloads are wire snake_case, sent raw. No `client.onChat` subscribers. Do not edit `mobile/vendor/**`, `src/ecosystem/common.ts`, `channels.ts` or `src/settings/*`.

## Tests (write first, see them fail, then implement)
These are the tests listed in plan Task P4-C2:
- install with the gate off: no `mutate` call and a policy error;
- install with the gate on: `mutate` is called with `timeoutMs: 150000`;
- a 504 triggers a re-fetch;
- `Object.keys` of the `useMcp()` result contains no custom or import action;
- the MCP OAuth callback_url is sent once, then polled to done, and expiry stops the polling;
- the `useSkills()` result has no delete;
- `run(id)` sends exactly one `automation.run`, then fetches the result;
- `groupByDay` ordering, including today, tomorrow and later, with jobs inside a day sorted by time;
- the automation update payload keys are snake_case.
