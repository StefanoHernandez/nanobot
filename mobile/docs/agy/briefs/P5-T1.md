## Context
We want a read-aloud (TTS) button on finished assistant messages using `expo-speech`, speaking in the active app language (`it` or `en`), with a Stop button while speaking. In addition, when the user dictates a message with the microphone (`VoiceButton`) and the Appearance setting **"Leggi ad alta voce le risposte vocali" / "Read aloud replies to voice messages"** is enabled, the assistant's reply is read aloud automatically once it finishes streaming.

### 2. `mobile/src/extras/speech.ts`
Build the TTS state store and auto-read tracker:
- Pure helper `export function stripMarkdownForSpeech(md: string): string`:
  - Strips fenced code blocks (` ```...``` `), inline backticks, markdown link URLs (`[label](url)` → `label`), headings `#`, HTML tags, and excess whitespace so `expo-speech` reads clean prose instead of raw code or URLs.
- Language helper `export function speechLanguage(): string`:
  - Maps `i18n.language` (or `prefs.language()`): `"it"` → `"it-IT"`, `"en"` → `"en-US"` (defaulting based on `i18n.language.startsWith("it") ? "it-IT" : "en-US"`).
- Zustand store `speechStore`:
  - `speakingId: string | null` (the `UIMessage.id` currently being spoken, or `null`)
  - `voicePending: boolean` (true after the user dictates via `VoiceButton` until the next assistant reply finishes or is cancelled)
  - `speak(id: string, markdownText: string): void`:
    - Calls `Speech.stop()`.
    - Computes `clean = stripMarkdownForSpeech(markdownText).trim()`. If `!clean`, sets `speakingId: null` and returns.
    - Sets `speakingId: id` and calls `Speech.speak(clean, { language: speechLanguage(), onDone: () => ..., onStopped: () => ..., onError: () => ... })`. The callbacks clear `speakingId` only if `get().speakingId === id`.
  - `stop(): void`:
    - Sets `speakingId: null`, `voicePending: false`, and calls `Speech.stop()`.
  - `toggle(id: string, markdownText: string): void`:
    - If `get().speakingId === id`, calls `stop()`; otherwise calls `speak(id, markdownText)`.
  - `markVoiceDictated(): void`:
    - Sets `voicePending: true` if `prefs.voiceAutoRead()` is true.
- Auto-read listener / hook:
  - When a finished assistant message renders (or transitions from streaming/`live` to finished in `MessageRow`), if `speechStore.getState().voicePending` is true and `prefs.voiceAutoRead()` is true:
    - Consume the flag (`speechStore.setState({ voicePending: false })`) and call `speechStore.getState().speak(m.id, m.content)`.
  - Also stop speech on profile switch (`sessionStore` state becomes `"none"`).

### 3. `mobile/src/screens/thread/MessageRow.tsx` and `VoiceButton.tsx`
- In `VoiceButton.tsx`:
  - Whenever a non-empty transcript is handed to `onTranscript(x)` (both on manual stop and via the callback passed to `useVoiceInput`), call `speechStore.getState().markVoiceDictated()` first.
- In `MessageRow.tsx`:
  - For a **finished, non-empty assistant answer** (`!live && !m.isStreaming && m.kind !== "trace" && !!m.content`, independientemente of whether `onLongPress` is passed):
    - Subscribe to `isSpeaking = useStore(speechStore, (s) => s.speakingId === m.id)`.
    - Render a compact action row at the bottom of the assistant message with an `IconButton`:
      - `icon={isSpeaking ? "stop-circle-outline" : "volume-high"}`
      - `accessibilityLabel={t(isSpeaking ? "speech.stop" : "speech.listen")}`
      - `onPress={() => speechStore.getState().toggle(m.id, m.content)}`
    - If `speechStore.getState().voicePending && prefs.voiceAutoRead()` when the message finishes (`!live && !m.isStreaming`), trigger the auto-read once in a `useEffect`.
    - Note on `memo(MessageRowImpl, same)`: since `useStore(speechStore, ...)` is a hook inside `MessageRowImpl`, React re-renders `MessageRowImpl` when `speakingId === m.id` changes even with `memo`. Verify this in tests.

## Tests (write first, see them fail, then implement)
In `mobile/test/extras/speech.test.tsx` (mock `expo-speech`, but use the real `speechStore`, `MessageRow`, `AppearanceSection`, and `prefs`):
1. `stripMarkdownForSpeech` removes fenced code blocks, inline backticks, and link URLs (`Check [docs](https://example.com) and \`\`\`js\nconst x=1;\n\`\`\`` → `"Check docs and"`).
2. A finished assistant `MessageRow` renders the `speech.listen` button (`volume-high`). Tapping it calls `Speech.speak` with the stripped text and `language: "it-IT"` or `"en-US"`, and switches the button to `speech.stop`. Tapping again calls `Speech.stop()`.
3. While an assistant message is still streaming (`isStreaming: true` or `live: true`), the listen button is **not** rendered.
4. `AppearanceSection` renders the `settings.voiceAutoRead` switch and toggles `prefs.voiceAutoRead()` in MMKV (`kv`).
5. With `prefs.setVoiceAutoRead(true)` and `speechStore.getState().markVoiceDictated()`, when an assistant `MessageRow` transitions from `isStreaming: true` to `isStreaming: false`, `Speech.speak` is called automatically once, and `voicePending` becomes `false`.
