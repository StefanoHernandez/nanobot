## Context
The app's main area (`mobile/app/(main)/`) needs a **side drawer**, the same way the nanobot WebUI has a sidebar with the list of chats.

Existing code (read it):
- `mobile/app/(main)/_layout.tsx` is a minimal Stack placeholder. **You replace it with a Drawer.**
- `mobile/app/(main)/index.tsx` is the placeholder home. Turn it into an empty state: the text "Scegli o crea una chat" / "Pick or start a chat", plus a "Nuova chat" button.
- `mobile/app/(main)/chat/[key].tsx` is the thread screen (Claude's). **Do not edit it.** It draws its own header (back, model badge, Stop). Inside the drawer, hide the drawer header for this route (`headerShown: false`). The drawer opens with an edge swipe.
- `mobile/src/state/chatsStore.ts` (read only):
  - `useChats(selector?)`
  - State `{ chats: ChatSummary[]; loading: boolean; refresh(); newChat(): Promise<string /*key*/>; newTemporaryChat(): Promise<string>; rename(key, title): Promise<void>; remove(key): Promise<void>; search(q): ChatSummary[] }`
  - `isWritable(key)`
  - `ChatSummary` comes from `@/lib/types`, with fields `key`, `title?`, `preview`, `updatedAt`, `runStartedAt?` and so on. Read the type.
- `mobile/src/state/sessionStore.ts`: `useSession()` returns `{session, state, profile}`. Read it for the exact shape.

## What to build
**Files:**
- `mobile/app/(main)/_layout.tsx` (Drawer, with a custom drawer content)
- `mobile/app/(main)/index.tsx`
- `mobile/src/screens/chats/ChatDrawer.tsx` (the drawer content, with the logic so it is testable)
- `mobile/src/screens/chats/ChatRow.tsx`
- i18n keys `chats.*` in it/en
- Test: `mobile/test/screens/chats.test.tsx`

**Drawer content, top to bottom:**
1. **Header.** Profile name (`useSession().profile?.name`) and `<StatusDot/>` on the right, plus an `IconButton` "settings" that runs `router.push("/settings")`. The route will exist later; the button can be there now.
2. **Buttons.** "Nuova chat" / "New chat" calls `newChat()`, then navigates to `/chat/<encodeURIComponent(key)>` and closes the drawer. "Chat temporanea" / "Temporary chat" does the same with `newTemporaryChat()`. Show a toast with the error message if either fails.
3. **Search field.** Filters with `search(q)`.
4. **List of chats** (FlatList), most recent first as the store returns them. Each `ChatRow` shows:
   - the title (fallback: preview, else "Nuova chat");
   - a one-line preview;
   - a small running indicator when `runStartedAt` is set;
   - a **read-only badge** ("sola lettura" / "read-only") when `!isWritable(key)`.

   Tapping a row navigates to `/chat/<encodeURIComponent(key)>` and closes the drawer. Highlight the currently open chat.
   Long-pressing a row opens a small menu (a `Sheet` or `Dialog` with two actions):
   - **Rinomina / Rename** opens a `Dialog` with a `TextField` prefilled with the title, then calls `rename(key, value)`.
   - **Elimina / Delete** opens a destructive `Dialog` saying "Eliminare <titolo>?" / "Delete <title>?", then calls `remove(key)`. If the deleted chat is currently open, navigate to `/`.
5. **Pull-to-refresh** calls `refresh()`.

**Rules:** touch targets ≥ 48 dp, colors from `useTheme()`, strings via i18n, safe-area insets.

## Tests (write first, run, see them fail, then implement)
Mock `useChats`, `useSession` and `expo-router`.
- Typing in search calls `search` and shows only the matching chats.
- A non-writable chat (`telegram:1`) shows the read-only badge.
- Long-press, then Delete, then confirm calls `remove("websocket:a")` exactly once. Cancel calls nothing.
- Rename calls `rename(key, "New title")` with the trimmed value.
- "New chat" awaits `newChat()` and then navigates to `/chat/websocket%3Anew1`.
