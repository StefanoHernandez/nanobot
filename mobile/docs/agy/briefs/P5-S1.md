## Context
Today `mobile/src/extras/share.ts` (`handleShare`) receives an Android share intent from `expo-share-intent` (wired in `mobile/app/_layout.tsx`) and immediately creates a new chat. We want two improvements:
1. **Broader Android intent filters** in `mobile/app.json` so sharing arbitrary files (PDF, Office docs, text, images, archives) to nanobot works, not just `text/plain` and `image/*`.
2. **A chat picker sheet (`SharePickerSheet`)** so when content is shared (text, link, images, or files), the user chooses **where** to put it: either **"Nuova chat" / "New chat"** or **any existing writable chat** (with a search box). Once chosen, the app navigates to that chat with the composer pre-filled (`draft` and/or `pendingFiles`). **Pressing Send in the composer is always required; nothing is auto-sent.**

- `"androidMultiIntentFilters": ["image/*", "application/*", "*/*"]`

### 2. `mobile/src/extras/share.ts`
Keep the existing `Intent` and `ShareDeps` types backward-compatible, and add a small Zustand store `shareStore` for the pending share payload:
- `export type PendingShare = { text: string; files: LocalFile[] };`
- `shareStore` holds `{ pending: PendingShare | null; clear(): void }`.
- `handleShare(intent: Intent, d: ShareDeps = real)`:
  - If `!d.hasProfile()`, toast `extras.noProfile` and call `d.navigate("/connect")` (unchanged).
  - Extract `text`: when `intent.type === "text" || intent.type === "weburl"` (or whenever `intent.text?.trim()` is present alongside files), trim `intent.text`.
  - Extract `files`: map `intent.files ?? []` to `LocalFile[]` (`uri` prefixed with `file://` when starting with `/`, `name: f.fileName || "file"`, `mime: f.mimeType || "application/octet-stream"`, `size: f.size ?? sizeOf(f.path)`).
  - If `!text && !files.length`, toast `extras.shareFailed` and return.
  - If `d.pickChat === false` is NOT set, default behavior for the UI flow:
    - Add an optional `openPicker?: (payload: PendingShare) => void` to `ShareDeps`.
    - In `real`, `openPicker: (p) => shareStore.setState({ pending: p })`.
    - When `d.openPicker` is provided (default in `real`), `handleShare` calls `d.openPicker({ text, files })` so `SharePickerSheet` opens!
    - Export `applyShareToChat(targetKey: string | "new", payload: PendingShare, d: ShareDeps = real): Promise<void>`:
      - Resolves `key = targetKey === "new" ? await d.newChat() : targetKey`.
      - Calls `d.navigate(chatPath(key))`.
      - If `payload.text`, sets the draft on `key`: if `targetKey !== "new"` and `threadStore.getState().threads[key]?.draft?.trim()` is non-empty, join with `"\n\n"` (`existingDraft + "\n\n" + payload.text`); otherwise `d.setDraft(key, payload.text)`.
      - If `payload.files.length`, merges or sets `d.setPendingFiles(key, [...existingPending, ...payload.files])`.
      - Clears `shareStore` (`shareStore.getState().clear()`).
      - On error (e.g., `newChat` rejects), toasts `extras.shareFailed`.

### 3. `mobile/src/extras/SharePickerSheet.tsx`
A `Sheet` (`open={!!pending}`, `onClose={() => shareStore.getState().clear()}`, title `t("share.pickChatTitle")`):
- Shows a compact preview summary at the top of what is being shared:
  - If `pending.text`: 1–2 lines of the text (`numberOfLines={2}`, muted).
  - If `pending.files.length`: file count / names chip or subtitle (`t("share.filesCount", { count: pending.files.length })`).
- Primary action button at the top: **"Nuova chat" / "New chat"** (`Button` with `title={t("share.newChat")}`), which calls `applyShareToChat("new", pending)` (with a `busy` guard so double-taps are ignored).
- A `TextField` search input (`label={t("chats.search")}`) to filter existing chats.
- A `FlatList` (max height ~320 dp) of writable, non-temporary chats from `useChats`:
  - Filter: `isWritable(c.key) && !chatsStore.getState().isTemporary(c.key)` (plus search query match via `c.title` or `c.preview`).
  - Each row renders `ListItem` (or `ChatRow`) with `chatTitle(c, t("chats.untitled"))`, preview subtitle, and `onPress={() => void applyShareToChat(c.key, pending)}`.
- Respect theme colors, `KeyboardAvoidingView behavior="padding"` if needed, and ≥ 48 dp touch targets.

## Tests (write first, see them fail, then implement)
In `mobile/test/extras/native.test.tsx`:

   - Tapping an existing chat row populates `threadStore` draft/pendingFiles for that chat and closes the sheet.
   - Tapping "New chat" calls `newChat` once (even on double-tap) and populates the new chat's composer state.
