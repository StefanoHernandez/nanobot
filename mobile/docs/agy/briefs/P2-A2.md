## Context
Claude's core is done. Read these files; do not edit them:
- `mobile/src/core/upload.ts`:
  - `type LocalFile = { uri, name, mime, size }`
  - `validateFiles(files, limits)`, which returns `{ok:true}` or `{ok:false, reason: "count"|"file_size"|"total_size"|"type", name?}`
  - `prepareImage(file, maxBytes)`
  - `ALLOWED_MIME`
- `useSession().session.limits` gives `{ max_count, max_file_bytes, max_total_bytes }`.
- `useThreadSlice(key)` (`mobile/src/state/threadStore.ts`) returns, among other things, `{ draft, pendingFiles: LocalFile[], setPendingFiles(files), send(text, opts?: { files?, ... }): boolean, sendError: string|null, uploading: boolean }`.
  - **The store owns clearing.** After a successful file send, the store clears `draft` and `pendingFiles` by itself. On failure it keeps them and sets `sendError`.
  - `sendError` codes: `count`, `file_size`, `total_size`, `type`, `upload_unavailable`, `upload_failed_<status>`, or other strings. Map them to i18n, with a generic fallback.
- `mobile/src/screens/thread/Composer.tsx` is the composer (T8). You extend it.

## What to build
**Files:**
- `mobile/src/screens/thread/AttachmentBar.tsx`
- `mobile/src/screens/thread/attachments.ts`, pure: `toLocalFile(asset)` mappers for the picker results
- Modify `Composer.tsx`
- i18n keys `attach.*` in it and en
- Test: `mobile/test/screens/attachments.test.tsx`

**Dependencies:** `npx expo install expo-document-picker expo-image-picker`. Check the SDK 57 docs for both.

**Behaviour:**
1. **Attach button.** An `IconButton` (`paperclip`) in the composer, left of the input and next to the EffortPill. It opens a `Sheet` with "Foto" / "Photos" (image picker, multiple, images only) and "File" / "Files" (document picker, multiple, `copyToCacheDirectory: true`).
2. **Adding files.** Map each picked asset to a `LocalFile`; use the asset's `mimeType`, or a fallback by extension, and its `size`/`fileSize`.
   - Images (`image/*`) go through `prepareImage(file, limits.max_file_bytes)` first, one at a time.
   - Then run `validateFiles([...pendingFiles, ...new], limits)`. If it fails, show a toast "<reason text>: <name>" and add nothing from that batch.
   - Otherwise call `setPendingFiles([...pendingFiles, ...new])`.
3. **AttachmentBar,** above the input when `pendingFiles.length > 0`. It is a horizontal list of chips, each with:
   - a thumbnail for images (`Image` with the local uri), else an icon by type;
   - the name, ellipsized, and the size (KB/MB);
   - a remove button (≥ 48 dp) that calls `setPendingFiles(without it)`.
4. **Send.**
   - Enabled when `draft.trim()` is non-empty **or** there are pending files, and not `uploading`.
   - It calls `send(draft.trim(), { files: pendingFiles })` when files are present; otherwise it behaves as today.
   - While `uploading`, show a small spinner on the send button and disable the attach button.
5. **Errors.** When `sendError` changes to non-null, show a toast with the mapped i18n text. The chips and the draft stay.
6. **Read-only chats** have no composer already. No change needed.

## Tests (write first, see them fail, then implement)

- The chip remove button calls `setPendingFiles` without that file.
- Send with an empty draft and 1 file calls `send("", { files: [f] })`.
