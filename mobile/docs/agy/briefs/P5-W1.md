## Context
We want a minimal Android **Home Screen Widget** (and, if straightforward in the same config plugin, an Android **Quick Settings Tile**):
- **Home Widget:** displays the active profile name and connection status ("Connesso" / "Non connesso" / "Nessun profilo"), and tapping it opens the app on a **new chat** via a deep link `nanobot://new-chat`.
- **Quick Settings Tile (`TileService`):** a single tile labeled "Nuova chat nanobot" / "New nanobot chat" that launches `nanobot://new-chat`. (Ruling per `REVIEWER.md §3b`: keep both minimal inside one Expo config plugin generating small Kotlin classes + XML resources during `expo prebuild`; if the Quick Settings Tile causes any Android 14+ `PendingIntent` / Gradle complication, drop the tile and document that in your report.)
- **In-app deep link handler:** when the app is opened via `nanobot://new-chat` (or route `/new-chat`) and the session is `"open"`, it creates a new chat (`chatsStore.getState().newChat()`) and redirects to `/chat/<key>`. If no profile exists, it redirects to `/connect`.

### 1. `mobile/app/new-chat.tsx` and `mobile/src/extras/widget.ts`
- In `mobile/src/extras/widget.ts`:
  - Export `export type WidgetStatus = { profileName: string | null; state: "open" | "connecting" | "offline" | "none"; updatedAt: number };`
  - Persist the latest status snapshot in `kv` under `"widget.status"` whenever `syncWidgetStatus(profileName, state)` is called, and if a native module `NanobotWidget` is present (`NativeModules.NanobotWidget?.updateStatus`), call it in a `try/catch` (no-op in Jest or when native module is absent).
  - Subscribe a lightweight listener `startWidgetStatusSync()` to `sessionStore` so changes to `profile` or `state` update `"widget.status"` automatically.
  - Export `handleNewChatIntent(deps?)`:
    - If `!profiles.activeId()`, navigates to `"/connect"` (`router.replace("/connect")`) and returns.
    - When `sessionStore.getState().state === "open"`, calls `const key = await chatsStore.getState().newChat()` and `router.replace(chatPath(key) as never)`.
- In `mobile/app/new-chat.tsx`:
  - A minimal route screen for `nanobot://new-chat`:
    - Renders a themed background with an `ActivityIndicator` and `t("widget.openingNewChat")`.
    - Uses an effect watching `useSession()`: if `!profiles.activeId()`, replaces to `"/connect"`; once `state === "open"`, calls `handleNewChatIntent()` once (guarded by a `useRef` so it never creates two chats). If `state === "offline"` or `"auth_error"`, replaces to `"/"` so the user sees the main screen and banner.

### 2. `mobile/plugins/withNanobotWidget.js`
An Expo config plugin (`@expo/config-plugins`: `withAndroidManifest`, `withDangerousMod`) that, during `expo prebuild -p android`, writes:
1. `res/layout/nanobot_widget.xml` and `res/xml/nanobot_widget_info.xml`:
   - A clean, minimal `RemoteViews` widget (`LinearLayout` with title `"nanobot"`, status `TextView`, and "New Chat" button/tap target).
2. `NanobotWidgetProvider.kt` (`AppWidgetProvider` in package `dev.nanobot.mobile`):
   - Reads the status from `SharedPreferences` (`nanobot_widget_prefs`, or defaults to `"nanobot"`) and sets a `PendingIntent` (`FLAG_IMMUTABLE | FLAG_UPDATE_CURRENT`) launching `Intent(Intent.ACTION_VIEW, Uri.parse("nanobot://new-chat"))` on widget tap.
3. Optional `NanobotTileService.kt` (`TileService` for Quick Settings):
   - On click, launches `Intent(Intent.ACTION_VIEW, Uri.parse("nanobot://new-chat")).addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)`.
4. Registers `<receiver android:name=".NanobotWidgetProvider" android:exported="true">` (with `APPWIDGET_UPDATE` and `@xml/nanobot_widget_info`) and, if included, `<service android:name=".NanobotTileService" ...>` in `AndroidManifest.xml` idempotently (no duplicate entries on repeated `prebuild`).
- **Important:** Do **not** commit or create `mobile/android/` directly (per `README.md`, `android/` is generated by CNG). Keep everything inside `mobile/plugins/withNanobotWidget.js`.

## Tests (write first, see them fail, then implement)
In `mobile/test/extras/widget.test.tsx`:
1. **Status sync (no secrets leaked):** `startWidgetStatusSync()` writes `{ profileName: "Home", state: "open" }` into `kv.get("widget.status")` when `sessionStore` changes, and never includes `baseUrl` or any token/secret.
2. **`/new-chat` route with open session:** rendering `<NewChatScreen />` when `state === "open"` calls `chatsStore.getState().newChat()` exactly once and calls `router.replace("/chat/websocket%3A...")`.
3. **`/new-chat` route with no profile:** when `profiles.activeId()` is `null`, rendering `<NewChatScreen />` redirects to `"/connect"` without calling `newChat()`.
4. **Config plugin unit test:** calling the exported manifest modifier function from `mobile/plugins/withNanobotWidget.js` on a mock AndroidManifest object adds `.NanobotWidgetProvider` once, and calling it a second time is idempotent (still 1 receiver entry).
