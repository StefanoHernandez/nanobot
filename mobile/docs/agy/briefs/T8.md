## Context
The thread screen (`mobile/src/screens/thread/ThreadScreen.tsx`, Claude's) currently renders a placeholder input, `ComposerSlot` (`mobile/src/screens/thread/ComposerSlot.tsx`). You replace it with the real composer, the same way the nanobot WebUI composer works.

Existing code (read it, do not edit it unless listed under "Files"):
- `mobile/src/state/threadStore.ts`: `useThread(key)` returns `{ draft, setDraft(text), send(text): boolean, running, stop(), … }`.
  - `send` handles everything: it sends a normal message, or a follow-up ("guida") while a turn is `running`, and it handles slash commands too. You only call `send(text)`.
  - `draft` is persisted per chat in the store. Use `draft`/`setDraft` as the input value, not local state, so the draft survives navigation.
- `mobile/src/extras/logic.ts`: `loadCommands(session): Promise<Cmd[]>` with `Cmd = { command, title, description, argHint?, acceptsArgs }`. `command` already includes the leading `/` (e.g. `"/compact"`); check it in a test with a real-looking mock and normalise if needed.
- `mobile/src/state/sessionStore.ts`: `useSession()` returns `{ session, state, profile }`. Load commands once per session (`useEffect` on `session`); on failure keep an empty list, no toast.
- `mobile/src/extras/EffortPill.tsx`: `EffortPill({ chatKey })` is a stub returning `null`; T10 implements it. Render it in the composer's left slot.
- UI kit `mobile/src/ui/components`, `useTheme()`, `useT()`.

## What to build
**Files:**
- Create `mobile/src/screens/thread/Composer.tsx`: `export function Composer({ chatKey }: { chatKey: string })`.
- Create `mobile/src/screens/thread/SlashMenu.tsx`: `export function SlashMenu({ query, commands, onSelect }: { query: string; commands: Cmd[]; onSelect(c: Cmd): void })`.
- Modify `mobile/src/screens/thread/ThreadScreen.tsx`: **only** swap `ComposerSlot` for `Composer` (import + JSX, nothing else). Then delete `ComposerSlot.tsx`.
- i18n keys `composer.*` in `it.json` and `en.json` (add keys, do not reorder or remove existing ones).
- Test: `mobile/test/screens/composer.test.tsx`.

**Behaviour:**
1. **Input:** multiline `TextInput` (RN core, styled with the theme; `TextField` is fine if it supports multiline cleanly). Grows up to ~6 lines, then scrolls. **Enter inserts a newline and never sends.** Placeholder "Scrivi a nanobot…" / "Message nanobot…".
2. **Left slot:** `<EffortPill chatKey={chatKey} />`.
3. **Send button** (`IconButton`, ≥ 48 dp):
   - Disabled when `draft.trim()` is empty.
   - On press: `const ok = send(draft.trim())`; if `ok`, `setDraft("")`. If not ok, keep the draft.
   - While `running`: the icon/label becomes "Guida" / "Steer" (accessibilityLabel too). Pressing it still just calls `send` (the store sends a follow-up). When `running` and the draft is empty, show a **Stop** button instead that calls `stop()`.
4. **Slash menu:**
   - Open when the draft starts with `/` and contains no space or newline yet. Filter commands whose `command` starts with the typed prefix (case-insensitive). Hide when nothing matches.
   - Render it **above** the input (inside the composer, max height ~240 dp, scrollable), each row: command + title, description in muted text. Rows ≥ 48 dp.
   - Selecting a command sets the draft to `"<command> "` (trailing space), which closes the menu, and keeps focus in the input.
5. **Layout:** the composer sits at the bottom; respect the bottom safe-area inset and the keyboard (check how `ThreadScreen` already wraps the slot; do not add a second `KeyboardAvoidingView` if one exists, mention it in the report).
6. Colors from `useTheme()`, strings via i18n.

## Tests (write first, run, see them fail, then implement)
Mock `useThread`, `useSession` and `loadCommands` (`jest.mock("../../src/extras/logic", …)` keeping the real exports via `jest.requireActual`).
- Typing text with a newline (`"a\nb"`) does not call `send`.
- Pressing send with `"  hi  "` calls `send("hi")` exactly once and then `setDraft("")`.
- Empty or whitespace-only draft: the send button is disabled (pressing it calls nothing).
- Draft `"/co"` with commands `/compact`, `/status`: the menu shows `/compact` only.
- Selecting `/compact` calls `setDraft("/compact ")`.
- `running: true` with a non-empty draft shows the "Steer"/"Guida" label; with an empty draft shows Stop, and pressing it calls `stop` once.
