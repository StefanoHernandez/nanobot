## Context
These are the app's own extras on top of the WebUI. The logic is already written and tested (Claude's T9). You build the UI.

Existing code (read it, do not edit it unless listed under "Files"):
- `mobile/src/extras/effort.ts`:
  - `useEffort(chatKey)` returns `{ state: EffortState | null, loading, apply, error }`, where `EffortState = { base: Preset; current: string | null; levels: string[] }`. `state` is `null` when the chat or model has no effort levels, or the chat is read-only.
  - `applyEffort(session, chatKey, state, level): Promise<string>` throws on failure. **Call `applyEffort` directly** from the sheet so you can `await` it and catch the error. Do not use the hook's `apply`, which swallows errors.
- `mobile/src/extras/logic.ts`:
  - `loadCommands(session): Promise<Cmd[]>`
  - `groupCommands(cmds)` returns `Array<{ group: "session"|"memory"|"agent"|"other"; items: Cmd[] }>`
  - `Cmd = { command, title, description, argHint?, acceptsArgs }`
- `mobile/src/state/sessionStore.ts`: `useSession()` returns `{ session, state, profile }`.
  - `state` is `"none" | "connecting" | "open" | "reconnecting" | "auth_error" | "offline"`.
  - `session.resume()` forces a reconnect.
  - `session.get<T>(path)` does an authenticated GET.
- `mobile/src/state/threadStore.ts`: `useThread(key).send(text)` sends a message or slash command.
- Stubs you replace: `mobile/src/extras/EffortPill.tsx` (`EffortPill({chatKey})`, already rendered by the composer) and `mobile/src/extras/StatusDot.tsx` (`StatusDot()`, already rendered in the drawer header). **Keep these exact names and props.**
- UI kit `mobile/src/ui/components` (`Sheet`, `Dialog`, `TextField`, `Button`, `IconButton`, `ListItem`, `toast`), `useTheme()`, `useT()`.

## What to build
**Files:**
- Replace `mobile/src/extras/EffortPill.tsx` and `mobile/src/extras/StatusDot.tsx`.
- Create:
  - `mobile/src/extras/EffortSheet.tsx`

- Modify `mobile/src/screens/thread/ThreadScreen.tsx`, **only** to:
  - add `<CommandDrawerButton chatKey={chatKey} />` in the header row before the Stop button, but only when `isWritable(chatKey)`;
  - add `<OfflineBanner />` directly under the header row.

  Change nothing else there.
- i18n keys `extras.*` in `it.json` and `en.json`. Add keys only; some `extras.*` keys already exist, so keep them.
- Test: `mobile/test/extras/ui.test.tsx`.

**Behaviour:**
1. **EffortPill:**
   - Render `null` when `useEffort(chatKey).state` is null.
   - Otherwise show a small pill `⚡ <level>` (level = `state.current ?? state.levels[0]`, with the label from i18n `extras.effort.<level>` falling back to the raw value). The touch target is ≥ 48 dp.
   - Tapping opens `EffortSheet`.
2. **EffortSheet** (`Sheet`, title "Ragionamento" / "Reasoning"):
   - A segmented row (or vertical list on narrow widths) with one segment per `state.levels`, in order, and the current one highlighted.
   - An "Applica" / "Apply" `Button`.
   - On Apply, `await applyEffort(session, chatKey, state, selected)` with `loading` on the button and repeat taps ignored (use a ref flag).
     - On success: close the sheet. `useEffort` refreshes by itself.
     - On error: `toast.show(error.message)`, keep the sheet open, and keep the previous level highlighted as current.
3. **CommandDrawerButton:**
   - An `IconButton` (icon e.g. `console-line`, label "Comandi" / "Commands") that opens a `Sheet`.
   - The sheet loads `loadCommands(session)` when opened and shows them grouped with `groupCommands`, each group under a header ("Sessione", "Memoria", "Agente", "Altro" / "Session", "Memory", "Agent", "Other").
   - Each row shows the command and its title; the description is muted.
   - Tapping a command:
     - When `acceptsArgs` is false: `send(command)`, then close.
     - When `acceptsArgs` is true: open a `Dialog` with a `TextField` (placeholder `argHint`). Confirm sends `` `${command} ${args.trim()}` `` (just `command` if args are empty), then closes both.
   - On a load error, show an inline error text with "Riprova" / "Retry".
4. **StatusDot:**
   - A 10 dp dot inside a ≥ 48 dp pressable. Colors:
     - green (`#22c55e`) when `open`;
     - yellow (`#eab308`) when `connecting` or `reconnecting`;
     - red (theme `destructive`) when `auth_error` or `offline`;
     - muted when `none`.

     These two status colors are the only allowed hex literals; put them in one exported const `STATUS_COLORS` in `StatusDot.tsx`.
   - `accessibilityLabel` is the state name via i18n.
   - Tapping opens `StatusPanel`.
5. **StatusPanel** (`Sheet`, title "Stato" / "Status"). On open, it fetches in parallel (each fetch independent; a failed one shows "—", never a crash):
   - `/api/settings`: show `version.current` and the active preset name (`model_presets.find(p => p.active)?.name`).
   - `/api/settings/version-check`: if it reports an available update, show "Aggiornamento disponibile: <version>". Read the vendor types under `mobile/vendor/nanobot/` (grep `version-check`) for the exact field names, and state in the report what you used.
   - `/api/settings/usage`: show token usage. Same rule: read the vendor types for the shape and show the totals.
   - Connection state and profile URL (`profile.baseUrl`). **Never show the secret.**
6. **OfflineBanner:**
   - Shown only after the state has been `reconnecting` or `offline` continuously for more than 3 s (a timer, cleared when the state changes).
   - Text "Non raggiungibile — Tailscale attivo?" / "Unreachable — is Tailscale on?" plus a "Riprova" / "Retry" button that calls `session.resume()`.
   - It does not hide content; the cached thread stays visible below it.

**Rules:** touch targets ≥ 48 dp, theme colors (except `STATUS_COLORS`), i18n strings, safe-area insets.

## Tests (write first, run, see them fail, then implement)
Mock `useSession`, `useEffort`, `applyEffort`, `loadCommands` and `useThread`. Use jest fake timers for the banner.
- Banner: with state `reconnecting`, it is not shown at 2.9 s and is shown after 3 s. Pressing Retry calls `resume` once. Switching to `open` hides it.
- Pill: `useEffort` state `null` renders nothing.
- Apply error: `applyEffort` rejects with `new Error("boom")`. The toast shows `"boom"`, the sheet stays open, and the current level is still highlighted.
- Apply success: `applyEffort` is called once with the selected level, even on a double tap.
- Command with args: tap `/goal` (`acceptsArgs: true`), type `"ship it"`, confirm. `send("/goal ship it")` is called once.
- Command without args: tap `/compact`. `send("/compact")` is called.
- The dot maps `open` to green, `reconnecting` to yellow, `auth_error` to destructive and `offline` to destructive.
