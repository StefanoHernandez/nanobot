## Context
When the agent edits files, nanobot sends `file_edit` events. The vendor projection already puts them on the activity messages as `UIMessage.fileEdits?: UIFileEdit[]`. Read the type in `mobile/vendor/nanobot/webui/src/lib/types.ts` around line 418:

- `UIFileEdit` is `{ call_id, tool, path, added, deleted, approximate?, status: "editing"|"done"|"error", operation?: "create"|"edit"|"delete", binary?, error?, diff?: { format: "unified", truncated?, text? } }`.

Today the app ignores these. We also want a thread-wide **image gallery**.

Existing code (read it; edit only what is listed under "Files"):
- `mobile/src/screens/thread/ActivityRow.tsx` renders an activity group (`messages: UIMessage[]`). Add the file-edit list inside it, after the existing per-message content.
- `mobile/src/screens/thread/media/media.ts`: `classify(m)`, `mediaName(m)`, `absoluteMediaUrl(baseUrl, url)`.
- `mobile/src/screens/thread/media/MediaViews.tsx` already has an inline image with a full-screen Modal. Reuse its patterns.
- `useSession().profile.baseUrl` turns relative media URLs into absolute ones. **Never log or toast media URLs.**
- `mobile/src/screens/thread/ThreadScreen.tsx`, the header row. You may add **one** gallery `IconButton` there, and nothing else.
- UI kit, `useTheme()`, `useT()`.

## What to build
**Files:**

**`diff.ts` rules:**
- `@@` lines become `hunk`.
- Lines starting with `+++` or `---` (file headers), `diff `, or `index ` become `meta`.
- `+` becomes `add`, `-` becomes `del`, and anything else becomes `ctx`.
- Strip the first char of add, del and ctx lines.

**FileEditList:** one row per edit, containing:
- an icon by `operation`: create, edit or delete;
- the `path`, middle-ellipsized if long;
- `+added` in green and `−deleted` in red, taken from theme tokens. If the theme has no green, add `success` to the theme the same way the other tokens are defined, and say so in the report;
- a small spinner when `status === "editing"`, and the error text in destructive color when `status === "error"`;
- "binario" / "binary" when `binary`.

Tapping a row toggles a `DiffView` below it, collapsed by default.

**DiffView:**
- Monospace, horizontally scrollable.
- add lines get a green-tinted background, del lines red-tinted, and hunk lines muted.
- Over 400 lines, show the first 400 plus "… N righe in più" / "… N more lines".
- When `diff.truncated`, show "Diff troncato" / "Diff truncated".
- When there is no `diff.text`, show only the summary row, not expandable.

**Gallery:**
- The route is `/gallery/<encodeURIComponent(key)>`. Read the messages with `useThreadSlice(key)`; it has no load effect, and the thread is already loaded because you come from it.
- Collect every image across messages:
  - `m.media` where `classify === "image"` and `url` is set;
  - `m.images` (`UIImage {url?, name?}`) where `url` is set.
  - Dedupe by url, in message order.
- Show a 3-column grid of square thumbnails.
- Tapping one opens a full-screen viewer with horizontal paging (FlatList `pagingEnabled`), a close button, and "i / N".
- The header has back and the title "Immagini" / "Images".

## Tests (write first, see them fail, then implement)
- `parseUnifiedDiff` on a small patch gives the right kinds, in order.
- `FileEditList` with a `done` edit shows `path`, `+3` and `−1`. Tapping it shows an added line's text. An `error` edit shows its error text.
- `DiffView` with 450 lines shows the "more lines" note.
- `GalleryScreen` with 2 messages and 3 images in total (one in `media`, two in `images`) renders 3 thumbnails. A `file`-kind media item is not included.
- The gallery button is absent when the thread has no images.
