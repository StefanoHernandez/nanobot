## Context
We want a complete multi-agent **Kanban & Bot Personas** system (`nanobot/ext/kanban.py`) inspired by Hermes Kanban, engineered specifically for `nanobot` and `luffy` (Arduino UNO Q):
1. **Bot Personas (`bots` table):** Since upstream `nanobot` only has a single `SOUL.md` and `agents.defaults`, we store distinct bot personas in SQLite (`id`, `name`, `icon`, `role_prompt`, `model_preset`, `allowed_tools`, `allowed_skills`, `max_concurrent`). When a bot works on a task or replies in board group chat, its `role_prompt` and task context are injected via `RuntimeContextBlock` (`nanobot/runtime_context.py`) without mutating `SOUL.md`.
2. **Boards, Tasks & Parent→Child Dependencies (`boards`, `tasks`, `task_links`, `task_runs` tables):**
   - Task statuses: `"triage" | "todo" | "ready" | "running" | "blocked" | "review" | "done" | "archived"`.
   - Priorities: `"low" | "medium" | "high" | "urgent"`.
   - Parent→child links (`task_links`): when a parent task completes (`status -> "done"`), any child task in `"todo"` whose parents are now **all `"done"`** automatically transitions to `"ready"` and receives its parents' `summary` and `artifacts`!
   - Recurrence (`recurrence_expr`, e.g. cron expression or `"every:3600s"`): when a recurring task completes, its run is recorded in `task_runs` and the task is re-queued (`status -> "todo"` with updated `scheduled_at_ms`).
3. **Persistent Session per `(task_id, bot_id)` & Review Loop:**
   - Each bot working on a task uses session key `kanban:{task_id}:{bot_id}`.
   - If the worker calls `kanban_request_review(task_id, summary, artifacts)` and a reviewer bot (or human) calls `kanban_review_verdict(task_id, approved=False, feedback="...")`, the task transitions back to `"ready"` with `review_feedback`, and when re-dispatched, the worker bot resumes its own `kanban:{task_id}:{bot_id}` session with full prior context plus the reviewer feedback!
4. **Workspace Isolation (`scratch` | `worktree` | `dir`):**
   - Parallel tasks default to `workspace_mode = "scratch"` (isolated directory `~/.nanobot/kanban_workspaces/<task_id>`) or `"worktree"` (isolated git worktree when `workspace_path` points to a git repo) so two bots never corrupt the same working tree.
5. **Board Group Chat with Anti-Ping-Pong Hop Limit (`board_messages` table):**
   - Humans and bots can post messages on a board (or a specific task).
   - Bots **never** auto-reply to every message. A bot is only queued to reply when explicitly mentioned via `@<bot_id>` (or `@<bot_name>`) AND the message's `hop_count < 3` (human messages have `hop_count = 0`; a bot reply triggered by a mention has `hop_count = parent.hop_count + 1`). At `hop_count >= 3`, no further bot-to-bot auto-triggers occur until a human posts.

### 1. `nanobot/ext/kanban.py`
Implement `KanbanStore` and `KanbanDispatcher`:
- SQLite database `~/.nanobot/ext_kanban.db` (WAL mode, configurable path for tests).
- Tables:
  - `bots`: `id TEXT PRIMARY KEY`, `name TEXT`, `icon TEXT`, `role_prompt TEXT`, `model_preset TEXT`, `allowed_tools_json TEXT`, `allowed_skills_json TEXT`, `max_concurrent INTEGER DEFAULT 1`, `created_at_ms INTEGER`
  - `boards`: `id TEXT PRIMARY KEY`, `title TEXT`, `description TEXT`, `max_concurrent INTEGER DEFAULT 2`, `created_at_ms INTEGER`
  - `tasks`: `id TEXT PRIMARY KEY`, `board_id TEXT`, `title TEXT`, `description TEXT`, `status TEXT`, `priority TEXT`, `assignee_bot_id TEXT`, `reviewer_bot_id TEXT`, `workspace_mode TEXT DEFAULT 'scratch'`, `workspace_path TEXT`, `recurrence_expr TEXT`, `scheduled_at_ms INTEGER`, `retries INTEGER DEFAULT 0`, `max_retries INTEGER DEFAULT 2`, `summary TEXT`, `artifacts_json TEXT`, `review_feedback TEXT`, `blocked_reason TEXT`, `created_at_ms INTEGER`, `updated_at_ms INTEGER`
  - `task_links`: `parent_id TEXT`, `child_id TEXT`, `PRIMARY KEY (parent_id, child_id)`
  - `task_runs`: `id TEXT PRIMARY KEY`, `task_id TEXT`, `bot_id TEXT`, `session_key TEXT`, `status TEXT`, `summary TEXT`, `artifacts_json TEXT`, `started_at_ms INTEGER`, `finished_at_ms INTEGER`, `error TEXT`
  - `board_messages`: `id TEXT PRIMARY KEY`, `board_id TEXT`, `task_id TEXT`, `author_type TEXT`, `author_id TEXT`, `author_name TEXT`, `content TEXT`, `hop_count INTEGER DEFAULT 0`, `created_at_ms INTEGER`
- Seed a default board `"main"` ("Main Board") and 3 default bots (`"coder"`, `"reviewer"`, `"researcher"`) on first init if tables are empty.
- Atomic state transitions & dependency resolution on `KanbanStore`:
  - `create_bot` / `update_bot` / `delete_bot` / `list_bots`
  - `create_board` / `list_boards` / `delete_board`
  - `create_task` / `update_task` / `move_task(task_id, status)` / `delete_task` / `get_task_detail(task_id)` (includes `parents`, `children`, `runs`, `messages`)
  - `add_dependency(parent_id, child_id)` / `remove_dependency(parent_id, child_id)` (rejects cycles!)
  - `claim_ready_tasks(now_ms=...) -> list[dict]`:
    - Atomically selects tasks in `"ready"` status (whose `scheduled_at_ms` is null or `<= now_ms`) up to the board's `max_concurrent` and each assignee bot's `max_concurrent`, marks them `"running"`, creates a `task_runs` entry with `session_key = f"kanban:{task_id}:{bot_id}"`, and builds the `RuntimeContextBlock` containing the bot's `role_prompt`, task description, parent summaries + artifacts, and any `review_feedback`.
  - Terminal worker actions:
    - `complete_task(task_id, summary, artifacts=[])`:
      - Marks current run `"done"`.
      - If `recurrence_expr` is set, computes next `scheduled_at_ms` and sets `status = "todo"` (keeping `summary`, `artifacts`, and `task_runs` history).
      - Otherwise sets `status = "done"`, and checks all child tasks in `task_links`: any child in `"todo"` whose parents are all `"done"` is automatically promoted to `"ready"`!
    - `request_review(task_id, summary, artifacts=[])`: sets `status = "review"`, stores `summary` and `artifacts`.
    - `review_verdict(task_id, approved: bool, feedback: str = "")`:
      - If `approved`: calls `complete_task(task_id, task.summary, task.artifacts)`.
      - If not `approved`: sets `status = "ready"`, `review_feedback = feedback`, and posts a system/reviewer comment in `board_messages`.
    - `block_task(task_id, reason: str)`: sets `status = "blocked"`, `blocked_reason = reason`.
    - `record_failure(task_id, error: str, transient: bool = False)`:
      - If `transient` (e.g. 429 / 502 / network timeout): requeues to `"ready"` **without** incrementing `retries`.
      - Otherwise increments `retries`; if `retries >= max_retries`, transitions to `"blocked"` with `blocked_reason = f"Max retries ({max_retries}) exceeded: {error}"`, else requeues to `"ready"`.
  - Group chat `post_message(board_id, content, *, author_type="user", author_id="user", author_name="User", task_id=None, parent_hop_count=0) -> dict`:
    - Computes `hop_count = 0 if author_type == "user" else parent_hop_count + 1`.
    - Parses `@<bot_id>` or `@<bot_name>` mentions in `content`.
    - If `hop_count < 3`, returns `triggered_bots: list[str]` of mentioned bots; if `hop_count >= 3`, `triggered_bots` is `[]` (anti-ping-pong cap).

### 2. `nanobot/agent/tools/kanban_tools.py`
Implement agent tools (`_scopes = {"core", "subagent"}`):
- `KanbanShowTool` (`name = "kanban_show"`): returns full task detail, parent summaries/artifacts, and comments.
- `KanbanHeartbeatTool` (`name = "kanban_heartbeat"`): records progress note on the active run/task.
- `KanbanCompleteTool` (`name = "kanban_complete"`): calls `store.complete_task(task_id, summary, artifacts)`.
- `KanbanRequestReviewTool` (`name = "kanban_request_review"`): calls `store.request_review(task_id, summary, artifacts)`.
- `KanbanReviewVerdictTool` (`name = "kanban_review_verdict"`): calls `store.review_verdict(task_id, approved, feedback)`.
- `KanbanBlockTool` (`name = "kanban_block"`): calls `store.block_task(task_id, reason)`.

### 3. HTTP & WebUI Mutation API in `nanobot/webui/ws_http.py`
- `GET /api/ext/kanban`: query `board_id` → returns `{ boards, active_board, bots, tasks, links, messages }`.
- `GET /api/ext/kanban/task?id=<task_id>` → returns `store.get_task_detail(task_id)`.
- WebUI mutations (and POST routes):
  - `"kanban.bot.save"` (`/api/ext/kanban/bots/save`): create or update a bot persona.
  - `"kanban.bot.delete"` (`/api/ext/kanban/bots/delete`): delete a bot persona.
  - `"kanban.board.create"` (`/api/ext/kanban/boards/create`): create a board.
  - `"kanban.task.save"` (`/api/ext/kanban/tasks/save`): create or update a task (including `parent_ids`).
  - `"kanban.task.move"` (`/api/ext/kanban/tasks/move`): `{ id, status }`.
  - `"kanban.task.delete"` (`/api/ext/kanban/tasks/delete`): `{ id }`.
  - `"kanban.task.review"` (`/api/ext/kanban/tasks/review`): `{ id, approved, feedback }`.
  - `"kanban.message.post"` (`/api/ext/kanban/messages/post`): `{ board_id, task_id?, content }`.

## Tests (write first in `tests/test_kanban.py`)
1. **Parent→child dependency promotion & artifact handoff:** Task P1 and P2 are parents of Child C1 (`status="todo"`). Completing P1 leaves C1 in `"todo"`. Completing P2 with `summary="API ready", artifacts=["src/api.py"]` automatically promotes C1 to `"ready"`, and `claim_ready_tasks()` injects P1 and P2's summaries and artifacts into C1's runtime context block. Cycle detection rejects `C1 -> P1`.
2. **Concurrency caps & atomic claim:** With board `max_concurrent=2` and bot `"coder"` `max_concurrent=1`, `claim_ready_tasks()` claims at most 1 task for `"coder"` and at most 2 across the board, using session key `kanban:<task_id>:<bot_id>`.
3. **Review loop & persistent session:** Worker calls `request_review` (`status -> "review"`). Reviewer calls `review_verdict(approved=False, feedback="Fix edge case")`: task returns to `"ready"` with `review_feedback`, and re-claiming uses the **same** `session_key` (`kanban:<task_id>:<bot_id>`). Calling `review_verdict(approved=True)` completes the task (`status -> "done"`).
4. **Failure handling (transient vs crash):** `record_failure(..., transient=True)` requeues to `"ready"` with `retries` unchanged (`0`). Two non-transient failures (`max_retries=2`) auto-block the task (`status == "blocked"`).
5. **Recurrence:** Completing a task with `recurrence_expr="every:3600s"` records the completed run in `task_runs` and re-queues the task to `"todo"` with `scheduled_at_ms > now`.
6. **Group chat anti-ping-pong hop limit:** User message (`hop_count=0`) mentioning `@coder` triggers `["coder"]`. Bot reply at `hop_count=1` mentioning `@reviewer` triggers `["reviewer"]`. Bot reply at `hop_count=2` mentioning `@coder` triggers `["coder"]`. Bot reply at `hop_count=3` mentioning `@reviewer` triggers `[]` (hop cap reached!).
