## fix1: Review fixes for artifacts security hardening and large-file streaming

### 1. Security hardening
- **`need` length clamping & validation (`ArtifactWebView.tsx`):**
  Enforced `readLength = Math.min(length, 1048576, resolvedSize - offset)`. Strict bounds checking validates integer parameters, `length > 0`, `offset >= 0`, and `offset < resolvedSize`.
- **Navigation allowlist:**
  Tracked with `isFirstLoadRef.current`. Only the initial load of `about:blank` or `data:` is permitted. Subsequent requests to `about:blank` or `data:` return `false`. External `http:` and `https:` navigations trigger the user confirmation dialog and open via `Linking.openURL` upon confirmation; other schemes are silently blocked.
- **XSS & HTML escaping:**
  Added shared `escapeHtml(str)` escaping `&`, `<`, `>`, `"`, and `'`. Applied to XLSX cell rendering and Mermaid diagram `<pre class="mermaid">` blocks.
- **CDN version updates:**
  Bumped Mermaid to pinned `11.4.1` (`@11.4.1/dist/mermaid.min.js`). Added documentation comment explaining that legacy SheetJS `xlsx@0.18.5` parsing risk is fully contained by the WebView sandbox (`connect-src 'none'`, no storage, no network, no secrets).

### 2. Big files & streaming
- **PDFDataRangeTransport streaming:**
  Replaced monolithic `loadAllChunks` for PDF with custom `PDFDataRangeTransport` subclass. Initial chunk is loaded at startup; subsequent chunk ranges requested by PDF.js via `requestDataRange(begin, end)` dispatch `need` messages to native code and return chunk data via `onDataRange`. PDF rendering uses `disableAutoFetch: true`, `disableStream: true`, `IntersectionObserver` for lazy page rendering, canvas pruning (> 3 pages away from viewport), and debounced zoom/resize re-rendering.
- **In-WebView Light Previews (ZIP central directory reader):**
  Implemented in-WebView light preview reading the ZIP End of Central Directory (EOCD) record and Central Directory headers from the tail of the archive over the chunk protocol:
  - **PPTX:** extracts `docProps/thumbnail.jpeg` and up to 30 `ppt/media/*` images, rendered as a responsive media gallery.
  - **DOCX:** parses `word/document.xml` extracting text from the first 200 paragraphs (`<w:p>`).
  - **XLSX:** parses `xl/sharedStrings.xml` and `xl/worksheets/sheet1.xml` displaying the first 200 rows with a "show more" button.
  - Compressed entries are inflated using `pako.inflateRaw` (pinned `pako@2.1.0`).
- **Inactivity timer:**
  The 20-second fallback timeout is now reset on every `need` chunk request, measuring idle inactivity rather than total download time.
- **`pptx-preview` API integration:**
  Wired `window.pptxPreview.init(container, opts).preview(arrayBuffer)`, resolving `postReady()` or catching errors to `postError()`.
- **Medium file streaming (2 MB - 10 MB):**
  `FileViewer.tsx` streams HTML, SVG, and Mermaid files between 2 MB and 10 MB over the chunk protocol rather than reading and inlining entire strings.
- **i18n in shell templates:**
  Passed translated strings (`loadingProgress`, `showMoreRows`, `loading`) into `buildShellHtml` for dynamic localized progress and UI labels.

## fix2: Second review round for artifacts (zip caps, reload flag, pdf zoom & chunk protocol)

### 1. Fixes implemented
- **First-load flag reset & WebView key:**
  `ArtifactWebView.tsx` maintains `shellVersionRef` which increments whenever `shellHtml` changes. `isFirstLoadRef.current = true` is reset before rendering, and the WebView receives `key={`webview-${shellVersionRef.current}`}` ensuring each shell source load is handled cleanly as a fresh initial navigation.
- **Zip parser caps inside web shell:**
  Hard caps added to light preview zip reader:
  - `cdSize <= 4 MB` and central directory count `<= 20000` entries;
  - per-entry `compSize <= 16 MB` and `uncompSize <= 64 MB` checked before and after `pako.inflateRaw`;
  - strict range validation `0 <= begin < end <= totalSize`;
  - cumulative requested bytes per light preview capped at 64 MB (`totalRequestedBytes <= 64 MB`).
  Any breach throws an error and posts `{"type": "error"}` to native.
  Exported pure `parseZipCentralDirectory` helper with `ZIP_CAPS` constants for standalone unit verification.
- **Fallback timer stability:**
  `onFallback` is stored in a ref (`onFallbackRef.current = onFallback`) to prevent unnecessary effect triggers from inline callbacks. The timer effect runs strictly on `[shellHtml]` and checks `isReadyRef.current` — once `ready` has been received, the timer is never scheduled or restarted again.
- **PDF pinch-zoom:**
  Implemented two-finger touch handlers and `visualViewport.resize` detection with 250 ms debounce. Updates zoom factor `scale = Math.min(4.0, Math.max(1.0, currentScale * factor))`, maintaining scroll anchor position and re-rendering visible pages.
- **PDF lazy placeholder sizing:**
  Placeholders maintain per-page dimensions with a `pageAspects` map. Initially sized using page 1's aspect ratio as an estimate, lazily querying `getPage(n).getViewport` as the placeholder approaches the viewport to correct heights.
- **Mermaid CDN version pinned:**
  Checked jsdelivr API (`https://data.jsdelivr.com/v1/package/npm/mermaid`) and pinned the latest 11.x release: **`11.17.2`** (`https://cdn.jsdelivr.net/npm/mermaid@11.17.2/dist/mermaid.min.js`).
- **Concurrent chunk requests & LRU chunk cache:**
  - `__chunks` cache implemented as a bounded LRU with maximum size of 32 MB (`32 * 1024 * 1024` bytes).
  - Cache entries and pending request callbacks are keyed by `offset:length` so shorter responses never falsely satisfy longer slice requests.
- **Out-of-range `need` handling:**
  RN replies with `window.__chunkError(offset)` when `offset >= resolvedSize`. The web shell's `__chunkError(offset)` rejects any matching pending chunk promises and posts `{"type":"error"}` to React Native.
