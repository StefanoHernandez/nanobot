## Doubts / decisions
- Navigation uses `router.navigate("/chat/<encoded key>")` (Drawer idiom, does not stack threads) for rows, "New chat" and "Temporary chat"; the brief only says "navigates". The test asserts `navigate`. Deleting the open chat uses `router.replace("/")`.
- The currently open chat is read from `usePathname()` (`/chat/<encoded>`), because the drawer content is outside the chat screen's params.
- The long-press menu is a `Sheet` with Rename/Delete, followed by the `Dialog`s. Dialog titles are new keys (`chats.renameTitle`, `chats.deleteTitle`) so they differ from the confirm labels.
- The `New chat` home button and the drawer's button share `useStartChat` (exported from `ChatDrawer.tsx`). Errors from new/rename/delete are shown as a toast with the error message (no secrets in those messages).
- Fallback title for empty chats is `chats.untitled` ("Nuova chat" / "New chat"), same text as the button.
- The drawer content and rows were only tested via unit tests; the actual Drawer layout and swipe were not run on a device.
